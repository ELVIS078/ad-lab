# Detection — T1566.001

## Deploying the rule

```bash
docker cp wazuh-rule.xml wazuh-single-node-wazuh.manager-1:/var/ossec/etc/rules/local_t1566.xml
docker exec wazuh-single-node-wazuh.manager-1 /var/ossec/bin/wazuh-control restart
```

## Validating it against `execute.ps1`

`execute.ps1` (in the parent folder) runs standalone for simplicity and
repeatability, so its direct parent process is `powershell.exe`, not
`WINWORD.EXE` — the Sigma/Wazuh rule above keys on the Office-app parent,
so running the script alone **will not** trigger it by design (that's
intentional: it keeps the baseline simulation safe to re-run without
Office installed).

To validate the rule end-to-end against the real parent/child chain it's
meant to catch, trigger the same payload from an actual macro-enabled
document on `client01`:

```vba
' Paste into a .docm's ThisDocument module, lab machine only.
' Mirrors execute.ps1's logic — same benign marker-file payload, now
' launched with WINWORD.EXE as the true parent process.
Private Sub Document_Open()
    Shell "cmd.exe /c powershell.exe -NoProfile -Command ""Set-Content -Path $env:TEMP\ttp_T1566_001_marker.txt -Value 'T1566.001 macro run'""", vbHide
End Sub
```

Open the `.docm` on `client01` with macros enabled, then confirm:

1. Sysmon Event ID 1 shows `ParentImage=...\WINWORD.EXE`, `Image=...\cmd.exe`.
2. The Wazuh dashboard shows a level-12 alert tagged `attack.t1566.001`
   under **Security events**.
3. Screenshot it, save to `../evidence/`.

## Query reference (KQL, if you swap in Microsoft Sentinel/Defender later)

```kql
DeviceProcessEvents
| where InitiatingProcessFileName in~ ("WINWORD.EXE","EXCEL.EXE","POWERPNT.EXE","OUTLOOK.EXE")
| where FileName in~ ("cmd.exe","powershell.exe","wscript.exe","cscript.exe")
```

## Query reference (SPL, if you swap in Splunk later)

```spl
index=sysmon EventCode=1
| where match(ParentImage, "(?i)\\\\(WINWORD|EXCEL|POWERPNT|OUTLOOK)\.EXE$")
| where match(Image, "(?i)\\\\(cmd|powershell|wscript|cscript)\.exe$")
```
