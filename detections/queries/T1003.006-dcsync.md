# Detection — T1003.006 DCSync

This is the highest-value detection in the whole lab: a confirmed
DCSync from a non-DC principal means full domain compromise, so it's
worth getting exactly right rather than copy-pasting a rule ID.

## Deploying the rule

```bash
docker cp wazuh-rule.xml <manager-container>:/var/ossec/etc/rules/local_t1003_006.xml
docker exec <manager-container> /var/ossec/bin/wazuh-control restart
```

**Before deploying**: run `execute.sh` once, find the resulting `4662`
event in the dashboard, and confirm the actual parent rule ID in your
ruleset (filter `rule.id` for the 6xxxx Windows-Security-4662 decoder
match). Swap it into `<if_sid>`.

## Validating it

1. Set creds (the password `jsmith` was reset to via the ACL-abuse step)
   and run:
   ```bash
   export COMPROMISED_USER=jsmith COMPROMISED_PASS='<reset password>'
   ./execute.sh
   ```
2. Dashboard → **Security events**, filter `rule.description` contains
   `DCSync`. Expect a **level-14 (critical)** alert naming `jsmith` as
   `SubjectUserName`, within seconds of the replication request.
3. Cross-check the raw event: `win.eventdata.Properties` contains one of
   the two replication GUIDs, `win.eventdata.SubjectUserName` is NOT
   `DC01$`.
4. Screenshot, redact, save to `../evidence/`.

## Query reference (KQL — Microsoft Sentinel/Defender)

```kql
SecurityEvent
| where EventID == 4662
| where Properties has_any (
    "1131f6aa-9c07-11d1-f79f-00c04fc2dcd2",
    "1131f6ad-9c07-11d1-f79f-00c04fc2dcd2")
| where SubjectUserName != "DC01$"   // replace with your actual DC list
| project TimeGenerated, SubjectUserName, SubjectUserSid, Computer
```

## Query reference (SPL — Splunk)

```spl
index=wineventlog EventCode=4662
    (Properties="*1131f6aa-9c07-11d1-f79f-00c04fc2dcd2*" OR
     Properties="*1131f6ad-9c07-11d1-f79f-00c04fc2dcd2*")
| search NOT Account_Name="DC01$"
| table _time, Account_Name, Object_Name
```

## Why `level: critical` / rule level 14

Unlike Kerberoasting (which only proves a weak password exists),
DCSync proves a principal already has the single most powerful
replication right in the domain — by the time this fires, the
realistic response is "treat as domain-wide compromise," not "investigate
and see." That's the distinction worth being able to articulate in an
interview: severity should track blast radius, not just technique
sophistication.
